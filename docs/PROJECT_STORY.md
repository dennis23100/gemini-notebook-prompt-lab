# Project Story

## From a teaching problem to an open-source tool

Gemini Notebook Prompt Lab did not start from the idea that “more prompts are always better.” It started from a teaching problem: **the same trusted source can require different wording, pacing, density, and visual treatment for different audiences.**

The project is informed by real teaching experience, including an in-person session with **100+ attendees**. That experience reinforced that audience fit matters alongside factual accuracy.

The open-source project turns that lesson into a reusable workflow:

```text
trusted source
   ↓
audience adaptation
   ↓
visual / output direction
   ↓
source-grounded prompt
   ↓
Gemini Notebook
   ↓
review / verification
```

## What the 100+ attendee session means — and does not mean

It is useful context for why the project exists. It shows that the underlying problem comes from real teaching rather than a purely hypothetical prompt collection.

It does **not** mean:

- 100+ GitHub users;
- 100+ installations;
- that every attendee used this current repository;
- that the current web app was deployed at that event.

The project will keep those claims separate.

## Public media policy

A short teaching clip exists. Before public repository use, any media should be reviewed for:

- identifiable attendees and presenters;
- permission / event recording expectations;
- visible private information on projected screens;
- whether a still image communicates the story more safely than the full video.

A privacy-reviewed still or short clip may be added later to the README and launch materials. The purpose is to explain the project’s origin, not to inflate usage metrics.

## What we want to prove next

The next evidence should come from the open-source project itself:

```text
real user
→ feedback / issue
→ triage
→ fix or PR
→ tests
→ release
→ follow-up
```

That maintenance loop is more valuable than collecting passive stars alone.
